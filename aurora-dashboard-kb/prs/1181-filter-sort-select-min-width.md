## Что сделано

Закрывает issue #1135: выпадающие списки фильтра/сортировки (`Select`/`ComboBox` из `ListToolbar`) меняли ширину в зависимости от текущего выбранного значения — короткий текст сжимал меню, длинный растягивал, из-за чего вся панель тулбара "прыгала" при смене значения. PR даёт этим селектам минимальную ширину, не трогая логику опций/выбора (описание PR прямо это утверждает — "Behaviour only", подтверждено дифом: изменения только в `className`).

4 коммита: первый (`4abd695`) наивно проставил `min-w-40` везде, второй (`6c1e79f`) переключил `FiltersInput` на `cn()`-merge вместо ручной конкатенации классов, третий (`ef6a382`) сузил область действия min-width во `FiltersInput` до брейкпоинта `sm:` — по прямому замечанию CodeRabbit о том, что на `sm`-брейкпоинте фильтр всё равно мог сжиматься, потому что несовпадающий по варианту класс не перекрывал конфликтующий `sm:min-w-0` — и четвёртый (`c089ec5`, текущий head) добавил changeset.

## Как это реализовано

`FiltersInput` (`FiltersInput.tsx`) получил два новых опциональных пропа и переключился на `cn()` (clsx + tailwind-merge) для склейки классов:

```tsx
// FiltersInput.tsx:12-13, 30-35
selectClassName?: string
comboboxClassName?: string
...
export const FiltersInput = ({
  filters,
  onChange,
  selectClassName = "",
  comboboxClassName = "",
}: FiltersInputProps) => {
```

```tsx
// FiltersInput.tsx:62, 73
className: cn("w-full sm:min-w-0 sm:flex-1", selectClassName),   // Select
className: cn("w-full sm:min-w-0 sm:flex-1", comboboxClassName), // ComboBox
```

Почему важен именно `sm:`-префикс у передаваемого класса: `cn` = `twMerge(clsx(...))` (`packages/aurora/src/client/utils/cn.ts`), а `twMerge` резолвит конфликты по **варианту** утилиты, а не по порядку в строке класса. Безпрефиксный `min-w-40` и `sm:min-w-0` — для `twMerge` разные варианты одной группы, конфликта он не видит и оставляет оба; а поскольку в скомпилированном Tailwind-CSS правила для `sm:`-варианта физически идут в стилевом файле после безпрефиксных, `sm:min-w-0` побеждает на экранах ≥`sm` независимo от того, в каком порядке классы стоят в атрибуте. Поэтому все 4 места, где `FiltersInput` реально используется, получили именно `sm:min-w-40` (не `min-w-40`) — это и есть правка третьего коммита, закрывающая находку CodeRabbit.

`SortInput` (`SortInput.tsx:31` — `className: selectClassName`, без базового класса и без `cn()`) такого конфликта не имеет — там простой `min-w-40` работает как задумано, поэтому все 10 мест, где рендерится `SortInput`, получили безпрефиксный `min-w-40` (7 — новая проставка пропа, 3 — расширение уже существовавшего `selectClassName` с `w-40` на `min-w-40`, чтобы сорт-селект не сжимался ниже 10rem, но мог расти при более длинном значении).
