## Как обновлять базу (инструкция для агента)

Выполняй шаги по порядку. Не сдвигай закреплённый коммит, пока не обновлены затронутые файлы.

1. **Определи диапазон.** Возьми закреплённый коммит `<PIN>` из шапки этого README. Выполни `git fetch origin` (если есть сеть), затем `git log --oneline <PIN>..origin/main`. Пустой список → база актуальна, сообщи об этом и остановись.
2. **Отфильтруй шум.** Коммиты `chore(version): update versions with Changesets` и правки lock-файлов не требуют анализа — из них бери только новые версии пакетов.
3. **Разбери существенные коммиты.** Для каждого: `git show --stat <sha>`, при необходимости — дифф значимых файлов. Проверяй утверждения по фактическому коду, а не по тексту коммит-сообщения: сообщение может приукрашивать или устареть.
4. **Определи затронутые файлы базы.** Стек, структура монорепо, версии, подводные камни → `01-overview.md`. Архитектура, auth, permissions, серверные/клиентские паттерны → `02-architecture.md`. API и сборка пакетов → `03-packages.md`. Команды, CI/CD, конвенции, релизы, тесты → `04-development-workflow.md`. Новые роутеры, роуты, design-docs, карта фич → `05-domain-map.md`.
5. **Обнови затронутые файлы.** Сохраняй язык и стиль каждого файла (01–05 — английский, README — русский). Устаревшие утверждения исправляй, а не дописывай рядом.
6. **Обнови README.** Сдвинь закреплённый коммит на новый HEAD `origin/main`, обнови дату, добавь запись в журнал обновлений сверху списка (в самом низу файла) в формате: `дата · <старый pin> → <новый pin> (N коммитов, PR #x–#y): суть изменений; смена версий`. Если существенных изменений не было — всё равно сдвинь pin и напиши «без существенных изменений». Журнал не сокращай — сохраняй все записи целиком.
7. **Отчитайся.** Кратко расскажи пользователю, что приехало в main и какие файлы базы обновлены.
