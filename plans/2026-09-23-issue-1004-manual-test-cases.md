### 1.3 Чем ставятся фикстуры — только UI

Всё состояние собирается действиями в дашборде, никакого `aws cli`. Используются ровно эти операции:

| Операция | Где |
|---|---|
| Create Bucket | Storage → Ceph → Buckets → **Create Bucket** |
| Enable Versioning | страница бакета → `⋮` → **Enable Versioning** |
| Upload Object | страница бакета → **Upload Object** |
| Create Folder | страница бакета → **Create Folder** |
| Delete Object / Delete Folder | меню строки → **Delete Object** / **Delete Folder** |
| посмотреть историю версий | меню строки живого объекта → **View Versions** |
| удалить одну версию | **View Versions** → меню строки версии → **Delete Version** / **Delete Marker** |
| восстановить удалённое | вкладка **Deleted** → меню строки → **Restore** |
| стереть удалённое навсегда | вкладка **Deleted** → меню строки → **Delete Object** (сносит все версии ключа разом) |

Две вещи, которые надо знать заранее, иначе фикстуры получатся не те:

- **Версионирование включается до загрузки.** Объекты, залитые раньше, получают `versionId: "null"` и истории не образуют.
- **Повторная загрузка файла с тем же именем не блокируется** — это и есть способ сделать старую версию.

Если каких-то пунктов меню нет — это права (`storage:*`), а не поломка: `useCephPermissions` fail-closed, при отсутствующем праве пункт просто не рисуется.

### 1.4 Реальный проект — правила безопасности

Группа **C** и кейсы **A2**, **E4** необратимо уничтожают данные. На реальном проекте это не абстракция:

- работать **только** с бакетами с префиксом `t1004-` — все фикстуры ниже так и названы;
- перед каждым деструктивным кейсом сверяться с именем бакета в заголовке модалки (она требует ввести имя — это и есть последняя проверка);
- никогда не запускать «Delete Versions» или «Empty Bucket» на бакете, который создал не ты в рамках этой проверки;
- бакеты проекта, не входящие в фикстуры, годятся только для **чтения** — например как крупный бакет, на котором интересно посмотреть время отклика в **A5**, но ничего не удаляется.

### 1.5 Приём «сжать потолок» — для всего, что про `isPartialScan`

Честный `isPartialScan` требует >20 000 записей версий в бакете. На реальном RGW создавать такой бакет ради UI-проверки дорого и долго — дешевле временно уменьшить потолки, ветка кода исполняется та же самая:

```bash
# packages/aurora/src/server/Storage/constants.ts — временно, на удалённой машине
S3_MAX_SCAN_PAGES = 1            # было 20
S3_MAX_KEYS_PER_REQUEST = 3      # было 1000
```

Тогда любой бакет из 5+ записей даёт неполный скан. Перезапустить `pnpm dev` после правки.

**Чего этот приём НЕ делает:** кнопку «Load more» в браузере объектов он не включает. `objects.list` берёт `MaxKeys` из входа процедуры (`objectRouter.ts:245`), а клиент шлёт свой `maxKeys: 1000` (`ObjectBrowserView.tsx:187`) — константа сюда не заходит. Для **B3** сжимается именно это клиентское число, см. сам кейс.

Откат после группы кейсов с потолком:

```bash
git checkout -- packages/aurora/src/server/Storage/constants.ts
git diff -- packages/aurora/src/server/Storage/constants.ts     # пусто
```

Патч наложен через `--index`, поэтому `git checkout --` возвращает файл к **запатченной** версии, а не к `dc918d47` — то, что нужно. Проверять надо именно `git diff` (рабочее дерево против индекса), а не `git diff --cached`: в `--cached` этот файл и должен отличаться от HEAD, он часть ветки.
### 1.6 Как смотреть запросы в DevTools

Клиент использует `httpBatchLink`, поэтому несколько tRPC-запросов склеиваются в один HTTP. Имена процедур видны **в пути URL**, через запятую:

```
/trpc/storage.ceph.containers.getState,storage.ceph.bucketPolicy.get,...?batch=1
```

Считать надо вхождения имени процедуры по всем запросам, а не число HTTP-запросов. Удобно: фильтр `getState` / `checkDeletedContent` в панели Network.

### 1.7 Фикстуры

Семь бакетов ставятся заранее, ниже. Ещё три (`t1004-d1`, `t1004-d2`, `t1004-d4`) создаются прямо внутри кейсов группы D — отдельно готовить их не нужно.

Каждый собирается за пару минут в UI; ниже — что именно должно получиться и как это увидеть, не выходя из интерфейса.

#### `t1004-plain` — неверсионированный непустой (A1)
1. Create Bucket → `t1004-plain`. Версионирование **не** включать.
2. Upload Object → любой файл, один.

Контроль: бейджа версионирования в шапке нет, в списке один объект.

#### `t1004-empty` — пустой неверсионированный (A2)
1. Create Bucket → `t1004-empty`. Больше ничего.

#### `t1004-ver` — версионированный с «живой» историей (A3, затем C1, B6)
1. Create Bucket → `t1004-ver`.
2. `⋮` → **Enable Versioning**, дождаться бейджа «Versioning Enabled».
3. Upload Object → `report.txt`, **три раза подряд** один и тот же файл.
4. Upload Object → `keep.txt`, один раз.
5. Upload Object → `gone.txt`, один раз → затем меню его строки → **Delete Object**.

Контроль в UI: во вкладке **All** видны `report.txt` и `keep.txt`; `report.txt` → **View Versions** → три записи, верхняя «Latest»; во вкладке **Deleted** виден `gone.txt`.

Зачем каждый: `report.txt` даёт старые версии, `keep.txt` — живой объект (`isEmpty: false`), `gone.txt` — delete marker.

#### `t1004-clean` — версионированный с ЧИСТОЙ историей (A5, A6)
1. Create Bucket → `t1004-clean`.
2. `⋮` → **Enable Versioning**.
3. Upload Object → 5 разных файлов, **каждый ровно один раз**. Ничего не удалять и не перезаливать.

Контроль: у любого объекта **View Versions** показывает **одну** запись, вкладка **Deleted** пуста.

Это та форма, где серверу нечего найти и он обязан досканировать бакет до конца — на ней и проверяются A5 (цена) и A6 (потолок).

#### `t1004-folders` — папки с удалённым содержимым (B1, B2, B3, B5, D3)
1. Create Bucket → `t1004-folders`.
2. `⋮` → **Enable Versioning**.
3. Create Folder → `alpha`, `bravo`, `charlie`, `delta` (четыре папки в корне).
4. Зайти в каждую → Upload Object → по одному файлу.
5. Зайти в `charlie` → меню строки файла → **Delete Object**. Вернуться в корень.
6. В корне: меню строки папки `delta` → **Delete Folder**.

Контроль: в корне во вкладке **All** видны `alpha`, `bravo`, `charlie` (три папки), `delta` отсутствует; во вкладке **Deleted** видны `charlie` и `delta`.

#### `t1004-case` — байтовый порядок ключей (C2)
Нужны четыре ключа, различающиеся только регистром: `A.txt`, `a.txt`, `B.txt`, `b.txt`, у каждого по две версии.

> ⚠️ На macOS два файла `A.txt` и `a.txt` не лежат в одной локальной папке — файловая система не различает регистр. Обход: сделать локально две папки, `up1/` с `A.txt` и `B.txt`, `up2/` с `a.txt` и `b.txt`, и грузить из них по очереди.

1. Create Bucket → `t1004-case` → **Enable Versioning**.
2. Upload Object из `up1/` → `A.txt`, `B.txt`. Повторить ту же загрузку второй раз.
3. Upload Object из `up2/` → `a.txt`, `b.txt`. Повторить второй раз.

Контроль: четыре строки в списке, у каждой **View Versions** показывает две записи.

#### `t1004-dm` — только delete marker, без реальных версий (A4, C3)
Собирается в два приёма, второй — нетривиальный, см. сам кейс A4.

1. Create Bucket → `t1004-dm` → **Enable Versioning**.
2. Upload Object → `only.txt`, один раз.
3. Меню строки → **Delete Object**.

На этом шаге в бакете есть и реальная версия, и маркер — это состояние нужно для **первой половины A4**. Как убрать реальную версию, оставив маркер, описано в A4 шагом 2.

## Приложение. Локальный мок — почему он здесь не годится

Оставлено на случай, если когда-нибудь встанет вопрос «а нельзя ли без RGW». `local-mock-backend/fake-backend.js` эмулирует версионирование ровно до той границы, за которой начинается эта ветка:

1. **`?versions` (ListObjectVersions) не отдаёт `<DeleteMarker>`** — маркеры сериализуются как обычные `<Version>` (`fake-backend.js:1611-1622`). `hasDeletedContent` всегда `false`, вкладка Deleted всегда пуста. Вся группа **B** и кейс **C3** невоспроизводимы.
2. **Пагинации нет** — `IsTruncated` захардкожен в `false`, `MaxKeys`/`KeyMarker` игнорируются. `isPartialScan` и потолок страниц недостижимы (**A6**, **B5**), «Load more» не появляется (**B3**).
3. **`ListObjectsV2` считает удалённый ключ живым объектом** — `contents` берёт `versions.find(v => v.isLatest)`, а маркер удаления тоже `isLatest`. `isEmpty` на версионированном бакете врёт (**A4**).

Осмысленны на моке только **A1, A2, A3, D1, D2, E2**. Дописать мок по этим трём точкам — отдельная задача, в скоуп #1004 не входит.
