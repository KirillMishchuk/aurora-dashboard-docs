## Цель и принцип

Скилл композиционный и детерминированный: код делает всё, что не требует суждения; оркестратор (Opus) только запускает агентов из списка, который печатает скрипт, и пишет формулировки (`texts.json`); агенты — Sonnet, **одна задача — один узкий агент**. Попытки навесить новую проверку на оркестратора или на агента с другой задачей проваливались (23–26.10) — не повторять. Поведение агента надёжно меняется только (а) отдельным узким брифом или (б) проверкой в коде (`save.py`/`assemble.py`/`render.py`), которая отказывает и заставляет агента переписать.

## Пайплайн (кратко; подробно — README/SPEC в `review-and-comment-pr-docs/`)

1 `collect.py` (режим full/rerun/status/update/none; exit 3 = вопрос) → 4 `briefs.py find` (describer или **describer-update**, finders `find-*`, **`pr-description`**, на update — `earlier-findings`) → 5 `briefs.py score` → scorers → `assemble.py` → `compose.md` → 6 Opus пишет `texts.json` → `assemble --texts && render.py` → fact-check → 7 индекс/Related (render) → 8 `prepare_comment.py` + явное «да» → 9 отчёт + отдельный вопрос про `DOCS/FOLLOW-UPS.md`.

Describer на update — отдельный бриф `describer-update.md` (пишет только то, что не покрывают прежние находки; QA нет).
- **Статусы earlier:** `fixed | partly | open | dropped` (`dropped` — старые находки о merge-конфликтах; конфликты больше не часть ревью ни в каком виде). `carried`: прежняя partly/open, чья нота ссылается `[[ref:]]` на новую находку, не считается в вердикте дважды.
- **Вердикт:** Must fix = Required Bug/Security без прецедента; остальное Required — Team call. Рекомендации: 🔴 Request Changes / 🟡 Approve with changes / 🟡 Approve with process to-dos / 🟢 Approve with nits / 🟢 Approve. Confidence есть и на update; draft на вердикт и Confidence не влияет (с 28.10).
- **Информативность находок:** `_candidates.md` — claim = последствие для пользователя/системы и условия; для находки по стандарту (B.x/Quick Reject) в evidence `example: <path:line>` — смёрженный образец вне PR (`save.py` проверяет; `example: none` = прецедент). `findings-format.md` — explanation начинается с последствия, правило последним; fix — что менять и откуда копировать. - **«Review comments not taken up»:** отсеянный кандидат со ссылкой на комментарий ревьюера публикуется строкой (автор+ссылка · claim · почему не находка).
