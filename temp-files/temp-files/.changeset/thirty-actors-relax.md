Security Groups list: the Shared filter now sends a correctly typed value (filtering no longer fails), filter options and pills show the same Yes/No labels as the table, the page header and toolbar stay visible while the list loads, and the search box triggers a debounced search instead of requiring Enter. The list can now also be filtered by Stateful. Kebab menus in the security group, rule and RBAC policy tables are vertically centred in their row again instead of dropping to the bottom of taller, multi-line rows.

Security group detail page: the redundant description under the group name is gone, the edit button now sits in the page header as "Edit Details", and an overflow menu next to it can delete the group — both matching the image detail page. Editing and deleting are hidden for groups shared from another project, as they already are in the list. The rule count above the rules table is gone, leaving the sort control and the "Add Rule" button (now without its plus icon) on their own row. Both detail tabs now use the same layout as the security group list: no extra vertical gaps between the toolbar and the table, an equally wide search box, and empty, loading and error states rendered inside the table instead of replacing it. The RBAC policies tab also loses its project count and the plus icon on "Share Security Group", and keeps its toolbar in place while the policies load. The kebab column in both tables no longer carries an "Actions" header, as in the security group list, and the rule row action now reads "Delete Rule" instead of just "Delete", the RBAC policy row action "Remove Policy" instead of "Remove". Wording is more specific throughout: the RBAC search box is right-aligned and reads "Search RBAC policies...", and the share dialog confirms with "Share Group". The delete dialog confirms with "Delete Group", matching the menu item that opens it. The Range column in the rules table is read correctly in three more cases: an ICMP rule that sets a type but no code now shows that type instead of a dash, ICMP written as "icmpv6" or as a protocol number is recognised as ICMP, and a rule whose port range fields are absent rather than null no longer renders the string "undefined".

The unused "network:security_group_rules:update" permission key has been dropped: security group rules are immutable in Neutron, so there is no update operation to authorize.

Security group rule and RBAC policy IDs are now validated and encoded before being interpolated into OpenStack request paths, matching the protection already applied to security group, floating IP and flavor IDs.
