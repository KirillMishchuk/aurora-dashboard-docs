# Скиллы Claude Code

Список скиллов (`/команд`), доступных в Claude Code в этой рабочей среде: встроенные — из официальных плагинов Anthropic, работают в любом проекте; проектные — специфичны для `aurora-dashboard`, лежат в `.claude/skills/` репозитория. Вызываются через `/имя-скилла` или триггерятся автоматически по описанию задачи.

> Список актуален на 24.07.2026 — состав встроенных скиллов зависит от того, какие плагины подключены у пользователя, и может отличаться в другой среде. Каталог всех доступных официальных плагинов Anthropic (не только подключённых у текущего пользователя) — в соседнем файле `claude-code-plugins.md`.

## Встроенные скиллы (плагины)

| Скилл                      | Описание                                                                                                                                                                                                                                |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `code-review`              | Ревью текущего диффа на баги и возможности упрощения/переиспользования/оптимизации с заданным уровнем усилий (low/medium/high/ultra). Флаг `--comment` постит находки инлайн-комментариями в PR, `--fix` — сразу применяет исправления. |
| `review`                   | Ревью существующего GitHub pull request по номеру/URL (в отличие от `code-review`, который смотрит на локальный рабочий дифф).                                                                                                          |
| `security-review`          | Комплексный security-ревью незакоммиченных изменений в текущей ветке.                                                                                                                                                                   |
| `simplify`                 | Ревью изменённого кода на переиспользование, упрощение, эффективность — и сразу применяет исправления. Только качество кода, багов не ищет (для этого — `code-review`).                                                                 |
| `verify`                   | Проверяет, что изменение реально работает — прогоняет затронутый флоу end-to-end, а не только тесты/тайпчек. Запускать перед коммитом нетривиальных изменений.                                                                          |
| `run`                      | Запускает и прогоняет приложение проекта, чтобы увидеть изменение в действии (CLI, сервер, TUI, Electron, браузерное приложение — по типу проекта).                                                                                     |
| `init`                     | Инициализирует новый файл CLAUDE.md с документацией по кодовой базе.                                                                                                                                                                    |
| `fewer-permission-prompts` | Сканирует прошлые транскрипты на частые read-only Bash/MCP-вызовы и добавляет allowlist в `.claude/settings.json`, чтобы реже спрашивать разрешение.                                                                                    |
| `update-config`            | Настройка `.claude/settings.json`: hooks для автоматических действий ("каждый раз когда X"), permissions, переменные окружения.                                                                                                         |
| `keybindings-help`         | Кастомизация горячих клавиш — ребиндинг, chord-сочетания, `~/.claude/keybindings.json`.                                                                                                                                                 |
| `loop`                     | Периодический запуск промпта или slash-команды с заданным интервалом (например, `/loop 5m /foo`); без интервала — модель сама выбирает темп.                                                                                            |
| `schedule`                 | Создание/управление облачными агентами на cron-расписании (routines), включая разовый запуск "выполнить один раз в 15:00".                                                                                                              |
| `dataviz`                  | Гайд по дизайну для любых чартов/графиков/дашбордов в любом выводе (HTML/React артефакт, SVG, matplotlib/plotly/d3/Recharts) — цветовые формулы, формы меток, layout.                                                                   |
| `artifact-design`          | Гайд по дизайну для Artifacts — как откалибровать объём дизайна под конкретный запрос.                                                                                                                                                  |
| `artifact-capabilities`    | Справочник по runtime-возможностям Artifacts (живые данные, общее состояние между зрителями, self-update) — читать перед объявлением `capabilities` в Artifact-туле.                                                                    |
| `claude-api`               | Справочник по Claude API / Anthropic SDK: модели, цены, параметры, стриминг, tool use, MCP, кэширование, подсчёт токенов, миграция между моделями.                                                                                      |
| `claude-in-chrome`         | Управление браузером через расширение Claude in Chrome — открытие страниц, клики, заполнение форм, чтение содержимого страницы.                                                                                                         |
| `skill-creator`            | Создание новых скиллов и улучшение существующих: интервью, черновик SKILL.md, тестовые прогоны с эвалами, сравнение baseline/with-skill, оптимизация description под триггеринг.                                                        |

## Скиллы проекта aurora-dashboard

Лежат в `aurora-dashboard/.claude/skills/`, работают только в контексте этого репозитория.

| Скилл | Описание |
| --- | --- |
| `create-plan` | Изучает архитектуру aurora-dashboard под конкретную задачу и составляет детальный план реализации (риски, шаги, тестирование, критерии готовности) через `dev-planner`, **не** пишет код. Сохраняет план файлом в `../DOCS/plans/` и обновляет индекс со статусом. Для случаев, когда план нужно сначала обдумать/показать, прежде чем реализовывать. |
| `implement-plan` | Реализует уже существующий план (из `create-plan` этой же сессии, из прошлой сессии или написанный вручную) через `dev-executor`, затем точечный security-проход по затронутым файлам. Если плана ещё нет — сначала запускает `create-plan`, потом себя на его выходе. |
| `triple-review` | Ревью текущих незакоммиченных изменений с трёх сторон параллельно (security, performance, architecture) через три специализированных суб-агента с объединением в одну сводку. Для ревью с одного угла — соответствующий агент напрямую; для обычного ревью качества кода — `/code-review`. |
| `quick-security-check` | Быстрый точечный security-аудит одного конкретного файла или компонента через `security-reviewer`, когда не нужен полный `triple-review` или `/security-review` всей ветки. |
| `create-pr` | Синхронизирует ветку с main, проводит через разрешение конфликтов и merge-коммит, генерирует описание PR из `.github/pull_request_template.md` и открывает draft PR через `gh`. |
| `rework-commits` | Разбирает дифф текущей ветки на последовательность мелких семантических коммитов (сначала БД/схема, потом бэкенд, потом фронтенд) с точкой отката и сверкой диффа до/после. |
| `update-kb` | Обновляет базу знаний проекта в `../DOCS/aurora-dashboard-kb/` после того, как в main влились новые коммиты — сравнивает с закреплённым коммитом, обновляет затронутые файлы базы, сдвигает pin, дописывает журнал обновлений. |
| `document-pr` | Вытягивает PR (по номеру/URL) через `gh`, делает полный разбор — что сделано, как, что затронуло в остальном монорепо (с примерами кода и file:line) — плюс ревью с confidence-scoring (5 параллельных агентов + фильтрация находок). Сохраняет отчёт в `../DOCS/aurora-dashboard-kb/prs/` и обновляет индекс. |

### Как устроены скиллы проекта

`create-plan`/`implement-plan`/`triple-review`/`quick-security-check` не содержат ревью-логику сами — они делегируют её пяти суб-агентам проекта из `.claude/agents/` (`dev-planner`, `dev-executor`, `security-reviewer`, `performance-reviewer`, `architecture-reviewer`), которые знают специфику стека aurora-dashboard (tRPC-процедуры, oslo.policy, отсутствие SQL/JWT/GraphQL/CORS и т.д.). Скилл описывает воркфлоу (когда каких агентов звать, в каком порядке, что делать с результатом), а знания о самом проекте живут в файлах агентов — при доработке агентов скиллы автоматически подхватывают изменения без правок в себе.
