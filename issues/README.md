# issues

Draft GitHub issues for `aurora-dashboard`, written here before they are opened on GitHub. Each file is the issue text pasted into GitHub by hand: the first line is the title in the repo's `[Type](scope): …` format, the rest is the body, following the matching template in `aurora-dashboard/.github/ISSUE_TEMPLATE/` (`bug_report`, `feature_request`, `task`, `epic`).

**Copying to GitHub:** each file starts with a properties (frontmatter) block — it is for Obsidian and must not end up on GitHub. Copy only the text below it: in Obsidian's reading view the properties block is not included in a text selection; in a plain editor, skip everything up to and including the second `---` line.

- **Naming:** `issue-<kebab-slug>.md`, one file per issue.
- **Why here:** keeps the wording reviewable and versioned before it goes public, and gives other work a stable local reference — the `temp-sync` skill looks here for the issue number when filling `# Related Issues` in a PR description (see [`../pr-descriptions/`](../pr-descriptions/)).
- **Issue number:** once the issue is opened on GitHub, add one line right under the title — `Opened as #<number> (YYYY-MM-DD)` — so the draft maps to its number without a trip to GitHub. That line is what `temp-sync` greps for when filling `Fixes #N`. No status or history is kept here: open/closed lives on GitHub.
- **Lifecycle:** drafts — once an issue is opened, GitHub is the source of truth; apart from the `Opened as` line, files are kept as a record, not updated afterwards.
